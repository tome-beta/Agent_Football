サッカーをしている時の人の思考順番を考えてみると、
状況を確認する→移動場所を決める→移動開始→移動終了
なのですが、何かしらのイベント（ターンオーバーなど）で処理に割り込みが入る形なのかな？と考えています


左様にございます。福留殿の考え方はかなり自然です。
 選手AIを「毎フレーム完全に考え直す存在」として作るより、一度判断した行動をしばらく継続し、重要イベントが起きたら割り込みで再判断する形の方が、サッカーらしくも、実装しやすくもなりまする。

基本の思考順番はかなり合っています

福留殿の整理はこうでしたな。

状況を確認する
→ 移動場所を決める
→ 移動開始
→ 移動終了


これはゲームAI的には、こう言い換えられます。

Observe     状況を見る
Decide      意図・目標を決める
Act         行動を開始する
Continue    行動を継続する
Complete    行動完了、または再判断


ただしサッカーでは、移動中に状況がどんどん変わります。
 そこで、

移動中にイベントが起きたら、再判断する


という割り込みが必要になります。

つまり「常時判断」ではなく「意図を持った行動 + 割り込み」がよさそう

毎フレームこうすると重いし、不自然です。

毎フレーム、全選手が最適地点を再計算する


これだと選手がフラフラします。
 一方で、こうすると自然になります。

一度「ここへ走る」と決める
少しの間はその行動を続ける
ただし重要イベントが起きたら考え直す


たとえば選手は、

今の意図: ライン手前で待つ
目標地点: x=320, y=180
継続時間: 0.7秒


のような状態を持つ。

そして、途中で、

ボールを奪われた
味方がパスを出した
自分の近くに敵が来た
オフサイドになりそう
パスコースが消えた


などが起きたら、割り込みで再判断します。

サッカーAIでは「イベント割り込み」がかなり重要

割り込みになりそうなイベントは、たとえばこれです。

攻守が切り替わるイベント
味方がボールを失った
味方がボールを奪った
ルーズボールになった


これは最優先の割り込みです。

攻撃時のポジショニングを続けている場合ではありません。
 即座に守備行動へ切り替えるべきです。

パスが出たイベント
味方がパスを蹴った
相手がパスを蹴った


これは全選手に影響します。

受け手はボール到達地点へ走る
近い相手はインターセプトへ向かう
他の味方はセカンドボールを狙う
守備側はカバーへ移る
ボール保持者が変わったイベント
保持者がAからBに変わった


攻撃側の非保持者は、支援先が変わります。

今までAに対してパスコースを作っていた選手は、
 Bに対してもう一度ポジションを取り直す必要があります。

自分がボールに触れたイベント
自分がボールを持った


これは即座に思考モードが変わります。

オフザボールの移動
→ パス / ドリブル / シュート判断


へ切り替えですな。

目標地点に到達したイベント
予定していた位置に着いた


このときは再判断します。

まだそこにいるべきか
次の場所へ動くべきか
パスを受けに行くべきか
戻るべきか

おすすめは「状態機械 + 割り込み」

実装としては、各選手に現在の状態を持たせるのがよいです。

type PlayerState =
  | "IDLE"
  | "SUPPORT_PASS"
  | "WAIT_ONSIDE"
  | "RUN_BEHIND"
  | "PRESS_BALL"
  | "MARK_OPPONENT"
  | "COVER_GOAL"
  | "CHASE_LOOSE_BALL"
  | "HAS_BALL";


各選手は今の状態を持つ。

player.state = "WAIT_ONSIDE";
player.target = { x: 320, y: 180 };
player.intentExpiresAt = currentTime + 0.8;


毎フレーム、まず割り込み条件を見ます。

function updatePlayer(player, world) {
  const interrupt = checkInterrupt(player, world);

  if (interrupt) {
    chooseNewIntent(player, world, interrupt);
  } else if (intentExpired(player) || reachedTarget(player)) {
    chooseNewIntent(player, world, "completed");
  }

  moveTowardTarget(player);
}

割り込みには優先順位をつけるとよいです

全部を同列にすると混乱します。
 優先順位をつけるのが肝です。

優先度 S: 自分がボールを持った / 攻守交代
優先度 A: パスが出た / ルーズボールになった
優先度 B: パスコースが消えた / 強いマークを受けた
優先度 C: 目標到達 / 行動時間切れ


疑似コードならこうです。

function checkInterrupt(player, world) {
  if (player.hasBall) return "HAS_BALL";
  if (world.possessionChanged) return "POSSESSION_CHANGED";
  if (world.ballBecameLoose) return "LOOSE_BALL";
  if (world.passStarted) return "PASS_STARTED";

  if (player.state === "WAIT_ONSIDE" && canRunBehind(player, world)) {
    return "RUN_BEHIND_CHANCE";
  }

  if (player.state === "SUPPORT_PASS" && passLaneClosed(player, world)) {
    return "PASS_LANE_CLOSED";
  }

  if (reachedTarget(player) || intentExpired(player)) {
    return "INTENT_COMPLETED";
  }

  return null;
}

「人間の思考」っぽくするなら、判断周期を分けるとよいです

人間の選手も、毎瞬間すべてをゼロから考えているわけではありませぬ。
 大きな判断と小さな調整を分けているように見えます。

ゲームでも同じにできます。

1. 高レベル判断

頻度は低め。

0.5秒〜1.0秒ごと


内容：

パスを受けるか
裏へ走るか
守備へ戻るか
プレスへ行くか

2. 低レベル調整

毎フレーム。

味方と近すぎたら少し避ける
敵が近ければ少し離れる
目標地点へ滑らかに向かう


こう分けると、フラフラしにくくなります。

// 低頻度
if (timeSinceLastDecision > decisionInterval || interrupt) {
  chooseNewIntent(player, world);
}

// 毎フレーム
applySteering(player, world);

実装モデルとしては「意図」を持たせるのがよいです

単なる state だけでなく、意図を持たせると扱いやすいです。

interface Intent {
  type: "SUPPORT" | "WAIT_ONSIDE" | "RUN_BEHIND" | "PRESS" | "COVER";
  target: Vec2;
  startedAt: number;
  minDuration: number;
  maxDuration: number;
  interruptible: boolean;
}


選手は現在の intent に従って動きます。

player.intent = {
  type: "WAIT_ONSIDE",
  target: calculateOnsideWaitingPoint(player, world),
  startedAt: world.time,
  minDuration: 0.4,
  maxDuration: 1.2,
  interruptible: true
};


いい点は、

フラフラしない
行動に継続性が出る
割り込み条件を管理しやすい
選手ごとの判断力を入れやすい

ことでござる。

選手パラメータとも相性がよいです

decision が高い選手は、割り込み判断が早い。

decision 高:
  イベントに素早く再判断
  無駄な走りを減らす

decision 低:
  古い意図を引きずる
  走り出しが遅れる
  オフサイドに残りやすい


vision が高い選手は、遠いイベントも見る。

vision 高:
  逆サイドのスペースも認識
  パスコースの変化に気づく

vision 低:
  近くの敵とボールだけ見る


positioning が高い選手は、WAIT_ONSIDE の位置が上手い。

positioning 高:
  ライン手前で待つ
  味方と被らない
  パスコースに顔を出す


こうすると、パラメータが単なる成功率ではなく、行動の質に効きます。

福留殿の案：

状況を確認する
→ 移動場所を決める
→ 移動開始
→ 移動終了

これはかなり良いです。

拙者の結論としては、サッカーAIは「常時最適化」ではなく、「意図を持った行動の継続」と「イベントによる再判断」で作るのが自然です。
 特にオフサイド絡みの動きは、この設計にしないと「裏へ走る」と「裏に居座る」の違いが表現しにくいと思いまする。


選手に状態遷移を持たえるのは、よさそうな検討結果に思います
これまでおそらく、毎ターン状況判断を入れていたので、選手がフラフラする動きをしていたように思います

左様にございます。かなり良い気づきだと思いまする。
 毎ターン、全選手がゼロから最適行動を選び直すと、サッカー選手というより「現在の評価値に引っ張られる粒子」になりやすいですな。

たぶん起きていたこと

これまでは、おそらく各ターンでこうなっていたのだと思います。

状況を見る
→ 一番スコアの高い行動を選ぶ
→ 少し移動する
→ 次ターンでまた最初から判断する


すると、評価値が少し変わるだけで、

今は前へ行く
次の瞬間は戻る
次は横へ
また前へ


となり、選手がフラフラします。

これは AI が馬鹿なのではなく、意図の継続性がないために起きる自然な症状ですな。

状態遷移を持たせると何が良いか

選手に状態を持たせると、

一度決めた行動を少し続ける
重要イベントが来たときだけ考え直す


という動きになります。

たとえば受け手なら、

WAIT_ONSIDE
  ↓ パスが出そう
RUN_BEHIND
  ↓ パスが出なかった / オフサイド危険
WAIT_ONSIDE


守備なら、

COVER_GOAL
  ↓ 自分が一番近い
PRESS_BALL
  ↓ 味方がプレスに入った
BLOCK_PASS_LANE


という感じです。

これにより、選手の動きに「今はこの意図で動いている」という芯が出まする。

最初から複雑な状態機械にせず、まずはこれくらいでよいと思います。

type PlayerIntentType =
  | "IDLE"
  | "HAS_BALL"
  | "SUPPORT"
  | "WAIT_ONSIDE"
  | "RUN_BEHIND"
  | "PRESS"
  | "COVER"
  | "CHASE_LOOSE_BALL";


選手には現在の意図を持たせます。

type PlayerIntent = {
  type: PlayerIntentType;
  target: Vec2;
  startedAt: number;
  minDuration: number;
  maxDuration: number;
};


そして毎ターン、

function updatePlayer(player: Player, world: World) {
  const interrupt = checkInterrupt(player, world);

  if (
    interrupt ||
    reachedTarget(player) ||
    intentExpired(player, world.time)
  ) {
    player.intent = chooseIntent(player, world, interrupt);
  }

  moveTowardIntentTarget(player, world);

という流れにします。

フラフラ防止に効く3つの仕組み
1. 最低継続時間

一度決めた意図は、少なくとも少し続けます。

minDuration: 0.4


たとえば SUPPORT に入ったら、0.4秒くらいは同じ意図を続ける。
 これで毎フレーム判断が反転するのを防げます。

2. 最大継続時間

ただし、ずっと古い意図を続けるのも問題です。

maxDuration: 1.2


1.2秒経ったら、状況が変わっていなくても一度再判断する。
 これで「古い判断を引きずりすぎる」ことを防げます。

3. 重要イベントだけ割り込み

割り込みは限定した方がよいです。

function checkInterrupt(player: Player, world: World) {
  if (player.hasBall) return "HAS_BALL";
  if (world.possessionChanged) return "POSSESSION_CHANGED";
  if (world.ballBecameLoose) return "LOOSE_BALL";
  if (world.passStarted) return "PASS_STARTED";

  if (player.intent.type === "WAIT_ONSIDE" && canRunBehind(player, world)) {
    return "RUN_BEHIND_CHANCE";
  }

  if (player.intent.type === "SUPPORT" && passLaneClosed(player, world)) {
    return "PASS_LANE_CLOSED";
  }

  return null;
}


これにより、どうでもよいスコア変化ではブレず、重要な局面では反応できます。

選手能力にも自然につなげられます

状態遷移は、パラメータ表現とも相性がよいです。

decision が高い
  → 割り込み判断が早い
  → 状況変化に強い

positioning が高い
  → WAIT_ONSIDE の位置がうまい
  → 味方と被りにくい

vision が高い
  → RUN_BEHIND のチャンスを見つけやすい

aggression が高い
  → RUN_BEHIND を選びやすい


つまり、能力値が単なる成功率ではなく、状態遷移のしやすさに効くようになりまする。

これはかなりカルチョビット的な個性に近いです。

まとめ

福留殿の見立ては当たりだと思いまする。

これまでのフラフラは、

評価関数が悪い


というより、

毎ターン判断し直していて、意図の継続性がなかった
