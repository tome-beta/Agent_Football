# 試合ルール・進行・ゲーム状態管理機能設計

## 概要
3対3のサッカーゲームにおける試合ルール、進行フロー、ゲーム状態管理の機能を定義します。

---

## 1. ゲーム状態（ステートマシン）

### 機能名：試合状態管理エンジン
**概要**：試合全体の進行段階を管理する状態マシン。試合の流れを一貫性を持って制御する基盤となります。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - 状態遷移図を定義（例：KICKOFF → PLAYING → GOAL_SCORED → RESTART → PLAYING → MATCH_END）
  - 各状態に滞在時間やタイムアウト条件を設定
  - イベント駆動（ボール移動、得点など）で状態遷移をトリガー

**定義する状態**：
- `MATCH_START`：試合開始前
- `KICKOFF`：キックオフ中
- `PLAYING`：通常のプレー
- `GOAL_SCORED`：ゴール成立時の停止
- `RESTART_SETUP`：再開前のセットアップ
- `HALF_TIME`：前半終了、後半開始前
- `MATCH_END`：試合終了
- `PAUSED`：一時停止（デバッグ用途）

---

## 2. チーム・選手構成とフォーメーション

### 機能名：3対3チーム構成定義
**概要**：各チーム3人の選手を管理し、基本的なフォーメーション（配置）を定義します。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - ポジション：GK（ゴールキーパー）1人、フィールドプレイヤー2人
  - 最小フォーメーション：1-2（GK1＋DF1＋FW1など）で十分
  - チーム情報：チーム名、色、戦術設定を保持
  - 選手情報：選手ID、ポジション、現在位置（X, Y座標）

### 機能名：フォーメーション管理
**概要**：ピッチ上の基本配置を定義し、選手の初期位置や推奨エリアを設定します。
- **優先度**：中
- **第一ステップに含めるか**：はい（最小限の実装）
- **実装メモ**：
  - ピッチサイズ：例えば 100m × 50m を座標で表現（0-100, 0-50）
  - ポジション別推奨エリア：GKはゴール前5m、DFはゴール前15m以内など
  - 第一ステップ：硬いフォーメーション制約は不要。選手AIが自律的に動くため、推奨位置は参考値程度に

---

## 3. 試合時間・タイマー管理

### 機能名：試合タイマーエンジン
**概要**：試合の進行時間を管理し、前後半制御およびタイムアウト機構を提供します。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - ターン制か実時間か：**ターン制を推奨**（選手AIの自律動作との同期が簡単）
  - 1ターン = 1サイクル（全選手が1回アクション）
  - 試合時間：例えば前半90ターン＋後半90ターン = 180ターン（小規模なため短時間）
  - ハーフタイム：前半終了時に一時停止、後半開始時に KICKOFF へ戻る
  - ターンカウンター：現在のターン数を記録

### 機能名：タイムアウト・期限制御
**概要**：特定の状態での滞在時間制限（例：GOAL_SCORED 状態で3ターン以上経過で自動的に RESTART へ）
- **優先度**：中
- **第一ステップに含めるか**：はい（基本的なもの）
- **実装メモ**：
  - 状態ごとにMAXターン数を設定（例：GOAL_SCORED は 5ターンで自動遷移）
  - ボールがプレー域外に出た場合も同様に制限

---

## 4. 得点判定・スコア管理

### 機能名：ゴール判定エンジン
**概要**：ボールがゴールラインを越えたか判定し、得点を成立させます。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - ゴールラインの定義：ピッチの両端（例：X=0 および X=100）
  - ゴール枠の定義：Y方向の中央付近（例：Y=20～30）、高さは無視（地上のみ）
  - 判定ロジック：ボールの位置がゴール枠内かつゴールラインを越えたか
  - GK以外のポジションの選手でも得点可（第一ステップは単純に）
  - オウンゴール：敵ゴールに対して得点したチームが得点者扱い（選手の所属チーム確認）

### 機能名：スコア管理・履歴記録
**概要**：各チームのスコア、得点タイミング、得点者を記録します。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - スコア保持：{ team_a_score: int, team_b_score: int }
  - 得点履歴：[ { team: str, player_id: int, timestamp: int, turn: int } ]
  - UI表示用：現在スコア、現在ターン

---

## 5. キックオフと試合再開

### 機能名：キックオフシーケンス
**概要**：試合開始時およびハーフタイム後に、ボール所有権と選手配置をリセットします。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - 試合開始：チームAからのキックオフと指定（またはランダム）
  - ボール位置：ピッチ中央（X=50, Y=25）
  - ボール所有権：キックオフチームに設定
  - ハーフタイム後：逆のチームがキックオフ

### 機能名：得点後の再開
**概要**：ゴール成立後、守備側からのキックオフ再開を制御します。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - GOAL_SCORED → RESTART_SETUP → KICKOFF （タイムアウト後）
  - 得点したチームの対抗チームがキックオフ権を獲得
  - ボール位置を中央にリセット

---

## 6. プレー中の基本ルール

### 機能名：ボール所有権・支配管理
**概要**：どのチームがボール支配権を持つかを追跡し、パス・シュートの判定に使用します。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - 所有権：closest_team（ボールに最も近いチーム）を毎ターン更新
  - パス判定：同じチームの選手へボール移動時は成功パス
  - 奪取判定：敵選手がボールに接触したら所有権切り替え

### 機能名：簡易的なボール物理（2次元）
**概要**：ボールの移動、減速、ゴール判定を実装します。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須。ただし選手AI・ボール物理担当の足軽と連携）
- **実装メモ**：
  - ボール位置：(x, y) 座標、速度 (vx, vy)
  - 毎ターン位置更新：x += vx, y += vy
  - 摩擦・減速：vx *= 0.95, vy *= 0.95 など簡易実装
  - ピッチ境界：y < 0 または y > 50 で OUT OF BOUNDS（タッチラインから戻す）
  - 本ドキュメントでは仕様定義のみ、実装は他の足軽に委譲

---

## 7. オフサイド・反則ルール（第一ステップでの判断）

### 機能名：オフサイド判定（**第一ステップは実装見送り**）
**概要**：オフサイドルールを実装するか検討します。
- **優先度**：低
- **第一ステップに含めるか**：いいえ
- **実装メモ**：
  - 理由：3対3 小規模試合ではゲームの複雑性が低く、オフサイド無しでも十分遊べる
  - 後戻し要素：選手AI改善後、必要に応じて追加
  - 実装時の仕様：ボール保有時の敵陣での最後列とボール位置を比較

### 機能名：反則・イエローカード・退場（**第一ステップは実装見送り**）
**概要**：ファウル検出と処罰メカニズム。
- **優先度**：低
- **第一ステップに含めるか**：いいえ
- **実装メモ**：
  - 理由：ゲーム初期段階では、選手AIの自律動作に集中すべき
  - 反則判定の例：身体接触の激しさ、危険プレー等（複雑）
  - 後戻し要素：ゲーム進化段階で導入

### 機能名：プレー域外・スローイン・ゴールキック（**第一ステップは簡略化**）
**概要**：ボールがピッチ外に出た場合の再開ルール。
- **優先度**：中
- **第一ステップに含めるか**：はい（簡略版）
- **実装メモ**：
  - 第一ステップ実装：OUT OF BOUNDS 時はボールを中央に戻す（スローイン・ゴールキック判定なし）
  - ボール再開権：ボール操作していなかったチームに与える
  - 後戻し要素：ゴールラインサイド判定、スローイン/ゴールキックの厳密化

---

## 8. チーム戦術パラメータ（第一ステップでの検討）

### 機能名：チーム戦術設定
**概要**：攻撃的/守備的などのチーム全体の傾向をパラメータ化します。
- **優先度**：中
- **第一ステップに含めるか**：はい（最小限の実装）
- **実装メモ**：
  - 基本パラメータ例：
    - `aggressiveness`：0～1（0=守備的、1=攻撃的）
    - `formation_width`：0～1（狭い←→広い）
  - 第一ステップでは2～3個の戦術パラメータに限定
  - 選手AIが このパラメータに基づいて行動判定を行う（AIエージェント担当）
  - ゲーム状態管理の観点では、パラメータ値の保持と更新インタフェースのみ

### 機能名：チーム設定の動的変更（**第一ステップは見送り**）
**概要**：試合中のハーフタイム時に戦術を変更するメカニズム。
- **優先度**：低
- **第一ステップに含めるか**：いいえ
- **実装メモ**：
  - 理由：初期段階では固定戦術で十分
  - 後戻し要素：ハーフタイム画面実装時に追加

---

## 9. 試合終了・勝敗判定

### 機能名：試合終了判定エンジン
**概要**：試合時間終了を監視し、MATCH_END 状態へ遷移させます。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - 試合終了条件：前半90ターン＋後半90ターン = 180ターン経過
  - ターン数チェック：毎ターン現在のターン数と上限を比較
  - 状態遷移：PLAYING → MATCH_END （ただし得点直後は GOAL_SCORED 経由）

### 機能名：勝敗判定・結果表示
**概要**：スコア比較で勝敗を判定し、結果を保存します。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：
  - 勝者判定：team_a_score > team_b_score ⇒ Team A Win
  - 同点時：Draw（延長戦は実装見送り）
  - 試合結果：{ winner: str, final_score: { team_a: int, team_b: int }, duration_turns: int }

## 10. ゲーム状態オブジェクト・データ構造

### 機能名：ゲームステート管理オブジェクト
**概要**：試合全体の状態を統一的に保持・更新するデータ構造。
- **優先度**：高
- **第一ステップに含めるか**：はい（必須）
- **実装メモ**：

```typescript
type GameState = {
  // 基本情報
  phase: MatchPhase;  // KICKOFF | PLAYING | GOAL_SCORED | ...
  turn: number;       // 現在のターン数 (0-180)
  half: 1 | 2;        // 前半/後半
  
  // チーム情報
  teams: {
    A: Team;          // { side, name, color, score, players, tactics }
    B: Team;
  };
  
  // ボール情報
  ball: {
    position: Vec2;   // { x, y }
    velocity: Vec2;   // { x, y }
    status: BallStatus;  // Free | Possessed | OutOfBounds
  };
  
  // イベント履歴
  scoreLog: ScoreLogEntry[];  // [ { team, playerId, turn }, ... ]
  
  // 試合結果（終了後）
  result: MatchResult | null;  // { winner, finalScore, durationTurns }
};
```

### 含める機能（**必須**）
1. ゲーム状態ステートマシン（7状態）
2. 3対3チーム構成・ポジション管理
3. ターンベースのタイマー・フロー制御
4. ゴール判定エンジン
5. スコア管理・履歴
6. キックオフと得点後の再開
7. ボール所有権管理（closest_team）
8. ゲームステートオブジェクト
9. 試合終了・勝敗判定
10. 簡易フォーメーション定義（推奨位置参考値）
11. 基本的なボール物理インタフェース（選手AI・ボール物理担当と連携）

- オフサイド判定

- 延長戦・PK戦

## 13. 他エージェントとのインタフェース

### 選手AI エージェント（足軽1など）との連携
- **入力**：ゲームステート（ボール位置、敵選手位置、戦術パラメータ）
- **出力**：各選手のアクション（移動先、パス先、シュート強度など）
- **責任分界**：
  - ゲーム状態管理：試合流れ、ターン進行、状態遷移
  - 選手AI：個別プレイヤーの意思決定

### ボール物理 エージェント（足軽2など）との連携
- **入力**：各選手のアクション、ボール状態
- **出力**：新しいボール位置・速度
- **責任分界**：
  - ゲーム状態管理：ボール所有権判定、ゴール判定、OUT OF BOUNDS 判定
  - ボール物理：ボール移動のシミュレーション、摩擦、衝突計算

### 武将エージェント（シーケンスオーケストレーション）との連携
- **責任**：毎ターンのゲームループ管理
  - 1. ゲーム状態確認
  - 2. 選手AIに行動決定を要求
  - 3. ボール物理を更新
  - 4. ゲーム状態を更新（得点判定、状態遷移など）
  - 5. 次ターンへ

## 14. 実装に関する検討事項

### 言語・フレームワーク
- **TypeScript** を使用（プロジェクト要件）
- union 型 + switch 文でステート遷移を実装、または軽量 FSM ヘルパユーティリティで管理

### テスト・デバッグ
- ゲーム状態の遷移テスト（キックオフ→プレー→得点→再開→終了）
- ゴール判定のエッジケーステスト
- ターンカウント正確性の確認

### パフォーマンス
- 180ターン × 複数試合でも高速に動作すること
- 状態オブジェクトのシリアライズ（ゲーム再生機能向け）の可能性
